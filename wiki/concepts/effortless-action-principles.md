# Effortless Action Principles

**Long-lived framework**: Greg McKeown's practical technique layer in
[[sin-esfuerzo]], the sequel to [[esencialismo]] — a set of execution
heuristics, not tied to any market/data point.

## The principles (Part II, "Effortless Action")

1. **Define "done."** A vague end goal makes a project effectively
   impossible to finish by design — you can spend time on it, abandon it,
   or fiddle with it indefinitely, but finishing requires a well-defined
   endpoint. Ask directly: how clear is your idea of what "done" looks
   like?
2. **Start with the obvious first action.** Ties to the minimum-viable-
   product principle from Silicon Valley/design thinking — build the
   smallest workable version first rather than the complete vision.
3. **Simplify — start from zero.** "Simplicity — the art of maximizing
   the steps *not* taken — is essential." To succeed at something, you
   have to finish it, and simplification is framed as what makes
   finishing possible.
4. **Progress: the courage to be bad at first.** "There is no mastery
   without mistakes, and no later learning without the courage to be
   bad [at first]." Directly comparable to [[growth-vs-fixed-mindset]]'s
   core mechanism (Dweck) — this is a concrete practical instance of
   growth-mindset thinking, ingested independently in the same batch.
5. **Pace: set upper and lower bounds.** Rather than aiming for a fixed
   daily target, use a simple rule — never less than X, never more than
   Y — as an easier-to-sustain alternative.
